## 0. 全体方針

- **二部構成**。第 I 部が成果報告（何を作り、なぜそう作ったか）、第 II 部が使い方説明。
  読者が違う（採点者 / 利用者）ので混ぜない。第 II 部だけ切り離して配れる形にする。
- **「動くもの」を見せるのが主役**。対称操作は静止画では伝わらないので、
  図は「操作前 → 途中 → 操作後」の連続コマで見せる。
- **判断の理由を書く**。何を作ったかより、なぜその設計にしたかが評価対象。
  特に「実装しなかったもの」とその理由は積極的に書く（§I-6）。
- 分量目安: 第 I 部 15〜20 ページ、第 II 部 5〜8 ページ、付録は必要に応じて。

## 第 I 部　成果報告

### I-1. はじめに（1〜2 ページ）

- **動機**: 結晶・分子の対称性は、対称要素の記号（点群・空間群）を暗記する形で教えられがちだが、
  「動かして重なる」という本質が体感されにくい。
- **目的**: 対称操作を 3D で実際に動かして見せ、さらにそれを問題として解かせることで、
  記号ではなく操作として対称性を理解させる。
- **成果物**: ブラウザで動く対称性ビューアーと、その上に乗せた 4 種類のクイズ。
- 素材: `docs/PROJECT_SPEC.md` の Purpose、`docs/PUZZLE_CONCEPT.md` §3（教育上の狙い）

### I-2. 対象と背景（2〜3 ページ）

- 対称操作の種類（回転 Cn / 鏡映 σ / 反転 i / 回映 Sn / 回反 -n / らせん / 映進）と、
  分子（点群・Schoenflies）と結晶（空間群・Hermann-Mauguin）で記法が違うこと。
- 既存教材・可視化ツールとの違い。**操作を見せるだけでなく問題として問う**点。
- 図: 操作の種類の一覧図（本アプリのスクリーンショットで作れる）

### I-3. 設計（3〜4 ページ）★ここが評価の中心

**中心的な設計判断: 解析層と表示層を `RenderData` で分離した**

```
CIF/XYZ → 解析(spglib/pymatgen) → RenderData → JSON → 表示(Three.js)
                                        ↓
                                   AtomMapping
                                        ↓
                                  game/ (判定ロジック)
```

書くべき点:

- **表示層は結晶か分子かを知らない**。`RenderData` が差を吸収する（`source_kind` で分岐）。
  結晶は分率座標で解析し `RenderData` で直交座標へ変換、分子は最初から直交座標。
- **判定は必ずサーバー側（Python）**。正解をクライアントに送らない。
  `game/` は `render_data` だけを消費し、DOM にも PyVista にも依存しない純 Python。
  → 各クイズが独立モジュールで、足し引きが容易。
- **1 クイズ = 1 モジュール**（`game/axis_orders.py` など）。試して残す/消すを設計に織り込んだ。
- 素材: `docs/PROJECT_SPEC.md`、`docs/PUZZLE_SPEC.md` §5・§8、`docs/VIEWER_GUIDE.md`

### I-4. 実装（3〜4 ページ）

- 構成と規模（下表）。
- サーバーは Python 標準の `http.server` のみ。外部 Web フレームワークを使っていない。
- 表示は Three.js。API は 25 エンドポイント。

| 項目 | 規模 |
|---|---|
| Python（解析・サーバー） | 約 14,400 行 |
| うち判定ロジック `game/` | 約 1,300 行 |
| JavaScript（ブラウザ表示） | 約 6,100 行 |
| テスト | 約 4,100 行 / 222 件 |
| 収録例題 | 結晶 32 種・分子 12 種 |
| API エンドポイント | 25 |

- 図: アーキテクチャ図（上の流れ図を清書）、画面構成図

### I-5. 4 つのクイズ（4〜5 ページ）★分量を割く

各クイズについて「何を問うか / なぜその形式か / 判定の難しさをどう解いたか」を 1 ページずつ。

| クイズ | 問い | 実装 |
|---|---|---|
| 回転軸 | 強調された軸は何回回転軸か | `game/axis_orders.py` |
| 操作あて | アニメで示した操作の種類（＋次数） | `game/operation_identify.py` |
| 合成 | 操作 A→B の合成と同じ 1 操作は何か | `game/composition.py` |
| 移り先 | この原子はどの原子へ移るか（クリック） | `game/atom_mapping.py` |

**書くと面白い技術的な山場**（設計の見せ場になる）:

- **見分けられない操作をどう扱うか**（操作あて）。CO2 の反転と垂直鏡映は動きが同一。
  除外すると CO2 が 0 問になり「対称性が無い」と誤読されるため、**除外ではなく統合**し
  「どちらでも正解」にした。全原子の移動先を丸めた `_visual_signature` で同一視する。
- **恒等と区別できない操作の除外**。平面分子の分子面鏡映は全原子が自分自身に写る＝動かない。
- **出題の偏り**。halite の普通モードは 137 問あるが答えの種類は 7 通り。
  そのまま乱択すると同じ答えばかり出る。**答えを明かさない group ID** を付けて種類均等に抽選。
- **回映/回反の次数は行列の周期でなく回転角から出す**。ベンゼンの主軸は S6 と S3 の両方を担うため、
  軸のラベルを操作名に流用すると「操作 S6」の正解が S3 の像になる。
- **等価な軸の集約**（回転軸クイズ）。正八面体の x/y/z の C4 を 3 回聞くのは冗長なので、
  群操作で軸を写して同値類を作り代表 1 本を出題（PUZZLE_SPEC §3.3b 案 A）。
- 素材: `docs/PUZZLE_SPEC.md`、`docs/sessions/SESSION_REPORT_2026-07-08.md`

### I-6. 作らなかったもの と その理由（1〜2 ページ）★差がつく章

作らなかった判断を根拠付きで書く。スコープ管理ができている証拠になる。

- **○×クイズ（偽の対称要素を混ぜる）**: 構想では「いちばん易しい入口」だったが見送り。
  偽要素の生成則を汎用に作るコストが高い（ずらし量が小さすぎると本物と区別できず、
  大きすぎると自明。妥当な範囲は構造の尺度に依存する）。加えて二択で当てずっぽうが効き、
  他の 4 クイズに比べて体験が薄い。
- **要素探索・閉包パズル**: 保留。群の閉包を体感させる狙いは良いが、UI の設計が別物になる。
- **スコア・タイムアタック・連続正解**: 入れない。1 問ごとの ○/× のみ。
- **回映軸クイズ**: 見送り（回転軸クイズの拡張だが、操作あてクイズで既に回映を扱う）。
- 素材: `docs/PUZZLE_SPEC.md` §10、`docs/PUZZLE_CONCEPT.md` §3.3・§5

### I-7. 品質保証（2 ページ）

- **222 件のテスト**。層ごとの内訳を表に。
- **headless Chromium による実機テスト 6 件**。人と同じ手順で実際にクイズを遊ぶ。
  「画面に出た操作名がサーバーの公開値と一致するか」「答えるまで 1 秒未満か」など、
  HTTP 境界の検証では捕まえられないものを固定している。
- **回帰の実例を 1 つ載せると説得力が出る**: 合成クイズの結果表示に `（S3）（S6）` という
  自己矛盾した二重表記が出るバグを、修正前のコードに戻すと同じテストが再現させた。
- **バージョン依存の落とし穴**: spglib の対称操作の順序に依存していた箇所があり、
  ライブラリ更新で解析結果が変わった。**一意に決まらない値をテストが固定していた**のが原因。
  特殊位置の原子は席対称群の全操作で生成されるため、生成操作は本来一意でない。
  → 教訓として書ける（「テストは仕様を固定すべきで、実装の偶然を固定してはいけない」）。
- 素材: `docs/sessions/SESSION_REPORT_2026-08-15.md`、`docs/REVIEW_NOTES.md`

### I-8. 既知の限界（0.5〜1 ページ）

隠さず書く。`docs/CLAUDE_HANDOFF.md`「未解決として報告書に載せるもの」に列挙済み。

1. ブラウザ E2E が 4 クイズ中 2 つ（回転軸・操作あては単体テストのみ）
2. ITC 表記の端ケース。601 操作中 583 件（97%）は ITC テーブルで解決、
   残り 18 件は計算経路で出力は妥当に見えるが**原典照合はしていない**
3. 移り先クイズで guess リングと C2 軸の線の色が近い場合がある
4. 合成クイズはらせん・映進を含む積を扱わない（点操作の積に限定）

### I-9. まとめと今後（0.5 ページ）

## 第 II 部　使い方説明（後付資料）

**単体で配れること**を優先する。第 I 部を読んでいない人が読む前提で書く。

### II-1. 準備（1 ページ）

```bash
git clone https://github.com/ono1105/symmetry_view.git
cd symmetry_view
scripts/setup.sh
scripts/serve.sh --mode puzzle
```

- **注意として明記**: `scripts/setup.sh` は Python の依存に加えて Three.js（`npm ci`）も入れる。
  これを飛ばすと画面は出るのに構造が描画されない。
- 動作環境（Python 3.11+ / Node.js / 対応ブラウザ）。
- PyVista は不要（既定で入らない）ことを一言。

### II-2. 画面の見方（1〜2 ページ）

- 起動 → パズル / 解析の選択画面。
- パズル画面の各部（描画エリア、元素ラベル、投影切替、カメラ操作、問題エリア）。
- 図: 番号を振ったスクリーンショット 1 枚で説明する。

### II-3. 4 つのクイズの遊び方（2〜3 ページ）

各クイズ 0.5〜1 ページ。**「問題の画面 → 答えた後の画面」の 2 枚**を並べる形式で統一。

- 回転軸クイズ / 操作あてクイズ（普通・難しい）/ 合成クイズ / 移り先クイズ
- 操作あての「難しい」ではらせん・映進の並進成分も答えることを明記。
- 移り先クイズは分子のみ。

### II-4. 解析モードの使い方（1〜2 ページ）

- 対称操作の一覧と選択、アニメーション再生、対称要素の表示。
- 自分の CIF / XYZ を読み込む方法。
- PNG / GIF 書き出し。

### II-5. 困ったとき（0.5 ページ）

- 構造が表示されない → `npm ci` を実行したか（最頻出）
- `--with-pyvista` でエラー → `requirements-pyvista.txt` を入れる
- 収録されている例題の一覧（結晶 32 / 分子 12）
