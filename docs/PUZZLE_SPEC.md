# パズル実装仕様

`PUZZLE_CONCEPT.md`（構想）を、現在のWebパズル実装に合わせて整理した仕様。

ステータス: **回転軸・操作あて・合成・移り先の4クイズを実装済み。**
最終更新: 2026-08-07

## 現在の実装状況

- パズルモードは解析モードのThree.js描画機構（`StaticStructureView`）を再利用する。
- 判定・出題ロジックは`crystal_viewer/game/`に置き、DOMやrendererに依存しない。
- 実装済みクイズ:
  - **回転軸クイズ**: 強調表示された軸の最高次数を1つ答える。直線分子のC∞は「無限回」。（`game/axis_orders.py`）
  - **操作あてクイズ**: アニメで示された操作の種類（＋次数）を答える。操作あてを選んだ後に **普通 / 難しい** を選ぶ。難しいでは、らせん・映進の並進成分も答える。（`game/operation_identify.py`）
  - **合成クイズ**: 操作A→操作B を順に見せ、合成（B∘A）と同じ1操作の種類・次数を答える。積は点操作に限定（らせん・映進は範囲外）。分子は直交座標の最近傍かつ一意な群元へ照合し、結晶は分率座標で合成する。標準Hall設定は1/24キーのO(1)経路、非標準原点は共有の汎用群照合へフォールバックする。（`game/composition.py`）
  - **移り先クイズ**: 操作名とその対称要素（軸・面・中心）を示して1原子を強調し、対象原子だけ操作を少し再生（曲線運動18%、直線運動10%の向きのヒント）、その原子が最終的にどの原子へ移るかを**静止した候補原子からクリック**で答える。平面・直線分子は任意の配向でも候補が重ならない向きへ自動整列する。分子限定はUIとサーバー判定の両方で強制する（結晶は周期像対応後）。（`game/atom_mapping.py`）
- クイズ選択画面は **回転軸 / 操作あて / 合成 / 移り先** の4カードを並べる。操作あての難易度は次の画面で選ぶ。
- スコア・連続正解・タイムアタック・偽要素は未実装。必要になってから設計する。

## 0. 確定した方針（ユーザー確認済み）

| 論点 | 決定 |
|---|---|
| 対象 | 分子と結晶。分子から開始し、現在は結晶の軸・回反・らせん・映進にも対応 |
| モード構成 | 起動時に**「パズル / 解析」選択画面**。入ったら**戻るボタンで選択画面へ戻らないと切替不可**（直接のモード間移動なし＝混乱防止）。CLIフラグで特定モードに直接入れる |
| 最初に作った問題 | **「何回回転軸か」**（軸を1本強調し、最高次数を1つ選ぶ） |
| 問題タイプの分け方 | ○×・合成 等は**毛色が違うので別モードの問題**として並べる。Lv1/2/3 の段階分けはしない |
| 難易度 | クイズモードとしては分けない。構造や操作の複雑さは、構造選択と出題内容の幅として扱う |
| スコア | **なし**（1問ごとに○/×のみ）。将来タイムアタックや連続正解数の追加は保留 |
| 偽の要素 | **見送り**（2026-08-15確定）。偽要素の生成コストに対して問題が面白くならないため |
| 固定色 | **今は作り込まない**。合成クイズ（順序を色で指すと分かりやすい）で必要になったら導入。単純な次数当てでは色は冗長・見づらいので、**実装しながら臨機応変** |

## 1. モード構成（アーキテクチャ）

```
起動
  └─ 選択画面（Analysis / Puzzle を選ぶ）
       ├─ Analysis モード … 現在のビューアー（解析・表示・アニメ）
       │     └─[戻る]→ 選択画面
       └─ Puzzle モード … パズルメニュー
             ├─ 問題タイプ一覧（回転軸 / 操作あて / 合成 / 移り先）
             │    └─ 問題を選んでプレイ
             └─[戻る]→ 選択画面
```

- **選択画面**が既定の入口。モード内には「別モードへ直接切替」する UI は置かず、**[戻る]で選択画面に戻ってから**選び直す。これで「パズル中に急に解析UIに入って混乱/バグ」を防ぐ。
- **モード切替時に状態リセット**（前モードの選択・強調・再生を持ち込まない）。
- **CLI 直接起動**: 例 `--mode analysis` / `--mode puzzle`（未指定なら選択画面）。開発・用途別に直接開ける。

## 2. パズルの構成

- パズルは**複数の問題タイプ**を持つ。現在のPuzzleメニューは **回転軸 / 操作あて / 合成 / 移り先** の4カードを並べる。
- 回転軸クイズは難易度を分けない。構造ごとの難しさは、プレイヤーが選ぶ構造そのものに委ねる。結晶の構造選択は、原子数が多すぎるものや出題できる操作が乏しいものを外し、パズル向きの代表例だけに絞る。
- 操作あてクイズは、選択後に難易度を選ぶ:
  - 普通: 回転・鏡映・反転・回映・回反
  - 難しい: らせん・映進（結晶のみ）。並進成分は **1/6 / 1/4 / 1/3 / 1/2 / 2/3 / 3/4 / 5/6** から選ぶ。
- 合成クイズ・移り先クイズは難易度を分けない（構造選択に委ねる）。移り先は分子限定、合成は分子・結晶とも可。
- 合成の候補生成は、積を作る前には視覚的に異なる操作を打ち切らない。積の種類ごとに operand の種類を層化して最大8問へ絞り、鏡映×鏡映から C2/C3/C4 などの教科書的な組合せを残す。

**将来の問題タイプ候補**（別モードの問題として順次追加）: ○×（本物の対称性か・偽要素あり）／要素を全部見つける。
- **回映軸クイズ**（Sn の最高次数）はユーザー判断で見送り（2026-08-06）。
- **○×・偽要素**は、説得力ある偽要素の自動生成が難しく、かつ問題タイプを増やしすぎないため保留（2026-08-06、判断は実装者に一任された）。まず本物の対称性の○×だけなら実装コストは低い（`/api/check_operation` の判定機構が既にある）。

## 3. 第一実装: 問題「何回回転軸か」

### 3.1 体験（予想 → 答え合わせ）

1. 分子を表示し、**1本の回転軸を強調**（強調は1本だけ。色固定は不要）。
2. 「この軸は何回回転軸ですか？」。選択肢 **2 / 3 / 4 / 6**、直線分子の主軸では **∞**。
3. **まず予想して選ぶ**。この時点ではアニメで答えを見せない（総当たりで解けてしまうのを防ぐ）。
4. 回答後、正解の回転操作をアニメで確認する。正解はその軸の**最高次数**。

### 3.2 正解の定義（判定ロジック）

- 軸の主次数 n に対し、正解は選択肢内の**最高次数**。
  - C2→2／C3→3／C4→4／C6→6。
  - C∞→∞。
- 純回転のみを数える。らせん軸は回転軸クイズの正解には含めない。
- 出題軸と回答後アニメは、解析モードと同じ`/api/symmetry_elements`と`/api/animation_path`の計算を使って一致させる。

### 3.3 端ケース（確定）

- **C∞（線形, CO2 等）**: 主軸を出題し **∞** を正解にする。CO2 の垂直 C2 軸（分子軸に垂直）は無限本ゆえ解析が列挙せず、v1 では出題しない。
- **C5・C7 等**（n が 2,3,4,6 と互いに素）: 選択肢内の正解は空集合。→ **v1 出題プールは主次数 2/3/4/6/∞ の軸に限定**（C5/C7 分子は初期除外）。将来「どれも当てはまらない」で対応。

### 3.3b 等価な軸の扱い（**案Aで確定・実装済み**）

高対称構造では幾何的に別方向でも**対称等価な軸**が複数ある（正八面体の x/y/z 3本の C4、ベンゼンの6本の C2 など）。「x軸の次数は？→y軸の次数は？」と同じ答えを繰り返すのは冗長。対応案:

- **案A（推奨）: 対称等価クラスで1本に集約**。群操作で軸の向きを写して同値類（軌道）を作り、クラスごとに代表1本を出題。原理的に正しく、他の問題タイプ（「等価な軸は何本？」等）に再利用可能。サーバー側で一度計算。
- **案B（簡易）: 回転次数の集合（＝答え）でグループ化**。同じ答えの軸は1問に集約。実装が軽く x/y 重複も消えるが、答えが同じで対称的に別種の軸（ベンゼンの原子通り C2 と結合通り C2、どちらも {2}）も1つに merge される。

いずれも「区別できる軸からランダムに1本」出題する点は同じ。

### 3.4 出題フロー（確定）

- 構造を選ぶ → その構造の（§3.3b でグループ化した）**区別できる回転軸からランダムに1本**出題。
- 解答して○/×表示 → **「同じ構造でもう一度」/「別の構造にする」**を選べる。
- **スコアなし・ヒントなし**（試し回しで自分で確かめる）。将来タイムアタック等は保留。

## 3b. 実装済み: 操作あてクイズ

1. 1つの対称操作をアニメーションで見せる。
2. プレイヤーは種類（必要なら次数）を答える。難しいでは並進成分も答える。
3. 正解は`/api/puzzle/operations/check`まで秘匿する。
4. 回答後、その操作の対称要素（軸・面・中心・映進矢印）と操作表記を表示する。

判定方針:

- 動かない操作（全原子が自分自身に写る）は恒等と区別できないので出題しない。
- 見た目が同じ操作は1問に統合し、複数正解を許す。
- 操作あてクイズは、UI上は1つの問題タイプ。その中で`normal`（点群操作）と`hard`（らせん・映進）を選ぶ。
- `hard`では、らせんの下付き添字・映進の面内移動から並進成分を求め、操作種類・次数・並進成分がすべて一致したときだけ正解にする。「なし」は選択肢に出さない。
- 高対称構造では答えの種類ごとに均等抽選するため、公開問題に不透明な`group` IDを持たせる。

## 4. 色について（保留・臨機応変）

- 単純な次数当て（この問題）や回映当ては、**1要素だけ強調**すれば足り、固定色は不要。色を足すと逆に見づらい/問題文が冗長になりうる。
- **合成の問題**（順序で結果が変わる）を作るときは、操作を**色で指す**方が分かりやすい可能性が高い。そのタイミングで「要素ごと固定色」を導入検討。
- よって固定色の作り込みは**先送り**し、必要になった問題タイプで実装しながら決める。

## 5. アーキテクチャ / API

- 既存の三層（Python 解析＝真実の源 / JSON / three.js 表示）を流用。
- **判定はサーバー側で一貫処理（確定）**。理由: `render_data` の軸は**操作ごとに分割**されており（例: ベンゼンの z 軸は C6用/C3用/C2用/S6用の別要素）、正しい次数集合を出すには **①同一直線の軸要素を幾何グループ化 → ②純回転(rotation_n)だけ抽出（S6等の回映は除外）→ ③次数集合** という非自明処理が要る。2箇所に置くとバグる。マイコンクライアントを薄く保つ方針とも合致。
- 新 API 例: `GET /api/puzzle/axis_orders`（構造の出題可能な軸グループと各正解次数集合を返す）。試し回しは既存 `/api/animation_path`＋原子一致で「その d が成り立つか」を返す/確認。
- モード分割は同一サーバ・同一資産で実現（別ページ・別サーバにはしない）。選択画面＋モード別パネル出し分け＋[戻る]＋`--mode`。

## 7. 操作種 → 問題タイプのロードマップ

全操作種を最終的に扱う。操作種で「自然な問いの形」が違うため、問題タイプ（モード）を分けて順次追加する。並進系は完全に後回し。

| 操作種 | 問題タイプ | 問いの形 | 位置づけ | 状態 |
|---|---|---|---|---|
| 回転 Cn | 何回回転軸か | 最高次数を1つ | 簡単 | 実装済 |
| 全種横断 | 今のアニメは何の操作か判別 | 種類＋次数当て | 導入向き | 実装済 |
| 並進・らせん・映進 | 難しいモードで種類＋並進成分 | 種類＋並進 | 結晶 | 実装済 |
| 合成 | A→B の合成と同じ1操作は？ | 種類＋次数当て | 難しい | 実装済 |
| 原子の移り先 | この原子はどこへ移る？ | 移り先をクリック | 具体的・合成の布石 | 実装済 |
| 回映 Sn（回反） | 何回回映軸か | 最高次数を1つ | 回転版の拡張 | 見送り |
| 鏡 σ／反転 i | 本物の対称か○× | 有無 | 別モード | **見送り** |
| 鏡 σ／反転 i | 全部見つける（要素探索） | 数 | 別モード | 保留 |

方針: 実装済みのものは**実際に遊んで残すか判断**（`game/` のモジュール単位で足し引き）。
○×＋偽要素は見送り（§10）。要素探索は保留のまま着手しない。
鏡σ・反転iは、操作あて・合成・移り先の各クイズの中で既に出題対象になっている。

- 判定・出題ロジックは **`crystal_viewer/game/`（純Python・`render_data` のみ消費・PyVista/DOM/生パーサ非依存）** に置く（`VIEWER_GUIDE.md` の Future Game Architecture 準拠）。**判定は一箇所（サーバー）**。

- 判定の**妥当性テスト**を付ける（ベンゼン主軸{2,3,6}＋垂直{2}、SF6 {2,4}/{3}/{2} など一意な教科書値で回帰）。

## 10. 決定事項（確定）

C∞含める・スコアなし・判定サーバー側・等価軸は**案A（対称等価クラス集約）**・クイズは回転軸/操作あて/合成/移り先の4つ・操作あて内で普通/難しいを選択・出題ランダム・同/別構造の選択・CLI `--mode`・予想→答え合わせフロー。合成はA/Bの正式名を表示し積だけを秘匿、移り先は操作名・対称要素を表示して対象原子だけを短くプレビューする。**未決定なし**。

**回映・回反の表記は操作自身の次数に従う（軸ラベルを流用しない）**。1本の軸が異なる次数の非真性操作を持つため（ベンゼン・BF3 の主軸は S6 と S3 = σh·C3 の両方を担う）、対称要素の表示記号をそのまま操作名に使うと「操作 S6」と表示した問題の正解が S3 の像になる。公開する `symbol`/`notation` は回転角から求めた次数で `S{n}` / `-{n}` に揃える。

**○×クイズ（偽要素）は見送り（2026-08-15確定）**。`PUZZLE_CONCEPT.md`§3.3では「レベル1・いちばん易しい」
と位置づけていたが、実装しないと決めた。理由は2つ。

1. **偽要素の生成が面倒**。「少しずれた鏡」を作るには、本物の対称要素からどれだけずらすかを
   構造ごとに決める必要がある。ずらしが小さすぎると本物と見分けられず、大きすぎると自明になる。
   妥当な範囲は構造の大きさ・原子間距離に依存し、汎用の生成則を作るコストが高い。
2. **問題として面白くならない**。答えが○か×の二択で、当てずっぽうでも半分当たる。
   既存の4クイズが「操作を見て名前を当てる」「移り先をクリックする」という具体的な操作を
   要求するのに比べ、体験が薄い。

この判断により、**クイズの追加は4つ（回転軸・操作あて・合成・移り先）で打ち切る**。
