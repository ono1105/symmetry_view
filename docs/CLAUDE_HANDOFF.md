### 収録物質はどこで決まるか

- 実体は `examples/cif/` と `examples/molecules/`。一覧と根拠は各ディレクトリの README
- `Halite.cif` と `BaTiO3.cif` 以外は `tools/generate_example_structures.py` の**生成物**。
  手で編集せず表を直して再生成する（この 2 件は `PROTECTED` で守られている）
- **どのクイズにどの構造を出すかはカタログの実測問題数で決まる**。
  `examples/example_catalog.json` の `puzzle_counts` が 0 の組合せはピッカーに出ない。
  `puzzle.js` に許可リストや分子式テーブルはもう無いので、**構造を足し引きしても
  JS を触る必要はない**。`tools/regenerate_example_assets.py --clean` を回すだけ
- **加えて `beyond_quiz_vocabulary`**（同じくカタログの計算値）が true の構造は
  回転軸・操作あて・合成・移り先の4クイズから外れる。回答の選択肢が 2/3/4/6 回に
  閉じているので、5 回軸を持つ構造は「問題数はあるが出題すると嘘になる」ため。
  生成時にログへ `analysis-only` と出る。**点群あてクイズだけは例外**（`isEligible()`
  in `puzzle.js`）: 点群記号を答えるだけなら 2/3/4/6 の語彙を要求しないため、
  準結晶クラスター2件もここにだけ出題される

## 環境で先に知っておくこと

このプロジェクトは**クローンしただけでは3D表示が動かない**。過去に一度これで丸1セッション溶かしている。

1. **Three.js が必要**。`crystal_viewer/web/node_modules` は生成物で git に入っていない。
   無いと HTML は 200 で返るのに `/vendor/three` が 503 になり、構造が一切描画されない。
   `scripts/setup.sh` が `npm ci` まで面倒を見る。
2. **npm が無い環境がある**。Ubuntu では `nodejs` と `npm` が別パッケージ。
   `setup.sh` は `npm` → `corepack npm@10` の順にフォールバックする。
3. **PyVista は既定で入らない**（2026-08-15 以降）。Web ビューアーだけで全機能が動く。
   テストは PyVista を要求するので、開発時は `requirements-dev.txt` を入れる。

```bash
.venv/bin/python -m pip install -r requirements-dev.txt   # テスト実行に必要
```

4. **ブラウザテスト**は playwright とブラウザバイナリが無ければモジュールごと skip する。
   `~/.cache/ms-playwright/` はユーザー単位の共有キャッシュで、**別プロジェクトと
   playwright のバージョンを合わせれば再ダウンロード不要**（2026-08-15 時点では 1.62.0 / chromium-1234）。

## 踏んではいけない地雷

- **spglib の対称操作の順序に依存しない**。バージョンで変わる。
  `identify_generation_operation()` が「最も近い操作」を選んでいたため、1e-16 の丸め誤差が
  勝者を決めており、spglib 2.7.0 で答えが変わってテストが落ちた（`bfdfad6` で修正済み）。
  特殊位置の原子は席対称群のすべての操作で生成されるので、**どれが正解かは一意に決まらない**。
- **`.claude/settings.json` はコミットしない**（ユーザー側の設定）。
- **回映の次数を「行列の周期」に直さない**。S3 と S6 は行列周期が両方 6 で、角度でしか
  区別できない（`PUZZLE_SPEC`§10）。角度から求めたうえで `360/n` が元の角度に戻るかを
  検算するのが正解。丸めるだけだと S10³(108°) が S3 として出題される。
- **手書きの除外リストを作らない**。`PUZZLE_CRYSTAL_EXAMPLES` と `MOLECULAR_FORMULA` は
  意図的に消した。除外が要るなら `game/catalog.py` に計算として書く。
- **`game/composition.py` の `_questions_cache` は `render_data` のオブジェクト識別がキー**。
  同じ dict を使い回して前後比較すると古い結果が返る。テストでは毎回読み直すこと。
- **`crystal_viewer/legacy/` は現役**。結晶解析が `symmetry_core.py` の上で動いている。
  `load_legacy_core()` が **import ではなくファイルパスで読み込む**ので、import を grep しても
  出てこない。名前と grep 結果だけ見て消すと CIF 経路が全部壊れる。
  （`archive/old_gui_attempt/` のほうは 2026-08-15 に削除済み。git 履歴に残っている）
- **`browser_ui.js` の `operationListRenderSignature()` に、概要データ由来のフィールドを
  忘れずに含める**。`element_sort_key`・`direction_filter_label`・`element_summary` は
  `summaries_ready` が立った後にしか揃わないが、署名は元々 `index`/`symbol`/`display_symbol`
  しか見ていなかった。ピッカー経由で構造を開くと、概要到着前に一度描画され、到着後の
  再描画が「署名が同じ」として握りつぶされ、**それらに依存する表示が永久に空のまま残る**
  （2026-08-17、`summariesReady` を署名に追加して修正）。この手の「非同期で後から埋まる
  フィールド」を行の見た目に使うときは、対応する `*RenderSignature()` に忘れずに足すこと。

## 未解決として報告書に載せるもの

隠さずに「既知の限界」として書く方針。

1. **ITC 表記の端ケース**（`REVIEW_NOTES.md` の「未対応の既知問題」）。
   同梱 15 結晶・1168 操作のうち 1163 件（99.6%）は ITC テーブル参照で解決する。
   計算経路に落ちるのは `BaTiO3`（R3m）の 5 件だけで、出力は妥当に見えるが
   **ITC 原典との照合はしていない**。
   （旧セットでは 601 操作中 18 件が計算経路だった。**結晶を**入れ替えたら数え直すこと:
   `itc_coordinate_summaries()` の一致数を全エクスポートで数えるだけ。ITC は結晶のみの話なので
   分子を足しても影響しない）
2. **合成クイズはらせん・映進を含む積を扱わない**（点操作の積に限定。仕様どおりの制限）。
3. **収録した結晶は理想化した生成物**で実測 CIF ではない。格子定数と Wyckoff 位置は
   文献値だが、温度因子や部分占有は持たない。対称性の教材としては問題にならないが、
   実データを見せる用途には向かない。

### 2026-08-15 に解消した項目

以前ここに挙げていたもの。報告書の §I-7（品質保証）の材料になる。

- ブラウザ E2E が 4 クイズ中 2 つ止まり → **4 クイズすべてを実機テストで踏む**（9 件）
- 移り先クイズの guess リングが軸と近い色 → **色相を離し**、リング色と軸色の色相差を
  静的テストで固定した。RGB のチャンネル差ではなく**色相距離**で測る点が要点
  （緑と空色はチャンネル差が小さいが混同しない。青と空色はその逆）
- 出題 0 の構造がピッカーに並ぶ → **カタログの実測問題数で絞り、到達不能にした**

### 2026-08-17 に解消した項目

- 操作リストで同一記号の行が連続し、どの軸/面か区別できない →
  **各行に方向のヒントを追加、複数操作が同じ要素にある場合は見出しでまとめる**
- 「Selected Operation」パネルが操作リストと画面上で離れていた →
  **操作リストの直後へ移動**
- カメラ設定が折りたたみの奥に隠れていた → **デフォルト展開にした**
- 対称要素の色とパズルのリング色が別々のファイルに分散していた →
  **`colors.js` に一元化**
- ピッカー経由で構造を開くと、概要データ（軸/面/中心のヒント等）が
  永久に空のまま描画され続けることがあった → **`operationListRenderSignature()`
  に `summariesReady` を追加**（上記「踏んではいけない地雷」参照）
